01 / The problem

They all write
to the same files.

Eighteen months ago you had one coding assistant. Today you have three running at once — Claude in one terminal, Cursor in another, Copilot in the editor. Not one of them knows the others exist.

Now put four people on the same repo. That is twelve agents, editing the same code, blind to each other. You find out at the merge. Or you do not find out at all.

02 / The layer

Claim. Coordinate.
Release.

01

Claim

Nothing gets written
without a lock.

A pre-tool hook fires before your agent touches a file and claims it against a shared, TTL-based lock table. If another agent holds it, the write is refused — not silently merged.

02

Coordinate

Locks that understand
your import graph.

Files do not exist independently. ./relay parses imports with tree-sitter and asks whether the change affects what someone else is editing — not just whether that exact path is open.

03

Release and sync

Every machine on
the same working state.

The post-tool hook releases the lock and the change propagates as a patch — not a project copy — to every teammate's clone through the room.

03 / No backend

You are the server.
You are the client.

None of this needs hosted infrastructure. One person on the team runs relay serve — that machine is the host. Everyone else connects over a tunnel (ngrok or Cloudflare), straight to that laptop. Nothing lives on infrastructure you do not own.

No account. No cloud index. Your laptop is the whole backend — the memory graph is one FalkorDB container on the host, and teammates query it through the room.

05 / Memory graph · FalkorDB

Locks say no.
The graph says why.

A lock stops two agents writing one file. It doesn't tell the blocked agent what the other one is doing, what was decided, or which prompt made the code look this way. ./relay turns every agent session, prompt, edit, block and decision — across every agent and teammate — into one FalkorDB graph, and hands it back to agents before and during their work.

  • Context at the conflict A denied lock quotes what the holder is working on.
  • Context before acting relay_session_brief briefs any agent on the files it's about to touch.
  • Every change explained Each edit links to the request behind it — no agent has to report anything.
  • Graph algorithms as tools PageRank over co-edits finds the hotspots; every answer ships its Cypher.

06 / How to get started

Two commands
on the host.

Install the CLI from npm and point ./relay at a project. Cloning through relay registers the workspace and installs the claim/release hooks for every agent you use — nobody has to remember a command afterwards.

host
$ npm install -g relaybrain   # the relay CLI, Node 20+
$ relay login              # GitHub identity, via the gh CLI
$ relay clone <repo-url>   # clone + register + install agent hooks
$ relay graph up           # optional: FalkorDB memory graph (Docker)
$ relay graph enable       # switch relay onto the graph
$ relay serve              # API + Mission Control on :3001
$ github.com/prakrititz/relayBrain ↗MIT · npm: relaybrain

Then open Mission Control → Team → Share to mint the invite link. Teammates run their own relay and join:

Command What it does
relay serve Start their local relay, then join with the host's invite link
relay pull Apply the host's current working state onto this clone
relay push Send your dirty working-tree files back to the room
relay doctor Walk the room chain and name the broken link

The memory graph runs on the host only. Teammates need no database — their graph queries go to the host's FalkorDB through the room. No Docker on the host? Point relay graph enable at a hosted FalkorDB instead.

Memory graph command What it does
relay graph up Start FalkorDB in Docker on localhost:6379 (browser UI on :3010)
relay graph enable [url] Save the URL and switch relay onto the graph — local Docker by default, or falkor://user:pass@host:port
relay graph status Is relay connected, when was each project last ingested
relay graph stats Node and edge counts per project
relay graph rebuild Pull existing agent history into the graph
relay graph seed A realistic five-agent demo graph to explore
relay graph disable Turn it off; locking and sync keep working without it
